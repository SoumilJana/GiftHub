## Done since 17 Nov

- **Phase 3, Secretly Bought (live):** reserve or buy someone's wish; other givers see "Already claimed", the owner sees nothing; Mark received names the giver and moves the wish to Received. Live updates come through `claim_signals`.
- **Phase 3.5, gift hand-off (live):** the giver picks "When will you give it?", GiftHub asks them "Did you give it?", and the receiver confirms. In-app only for now; Phase 5 adds notifications.
- **Phase 3.6, couple and group Circles (live).**
- **Phase 3.7, navigation and motion (live).** Rules are in `DESIGN.md` → Motion.
- **Phase 4, link reading (done):** paste a link and the name, price and photo fill in. Order of tries: Cloudflare → Supabase (`parse-url`) → scrape.do → the pre-filled form. Link test: 85% of 74 links complete (target 80%). Write-up: `docs/link-reading-2026-11-19.md`.
- **Phase 4.5, pre-beta check (so far):**
  - **Edge-case tests** (`supabase/rls-tests/edge.test.mjs`): found and fixed 3 bugs. A reservation could leave a wish stuck as "claimed" after it was unshared or the giver left; a too-big price or made-up currency gave a raw error; photo links weren't checked.
  - **Security pass:** the link reader now checks every redirect and looks up every address, so it can't be pointed at internal addresses. Page security headers are on (`web/public/_headers`). The old /demo mockup is no longer deployed. The sign-in return link is stricter.
  - **Cloudflare Turnstile** on sign-up, sign-in, Google sign-in, email links and password reset; Supabase checks it.
  - **Security Advisor:** `rls_auto_enable()` locked down; the other warnings are intended (details in the plan).
  - **Dashboard:** email confirmation on, minimum password length 8, "Secure password change" on.
